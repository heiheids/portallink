# 文件读取与索引规范

> 适用目录：`E:\Project\portallink\`
> 适用对象：任何在本工作目录里读文件、搜代码、看反编译输出、翻日志的操作。
> 版本：1.0（2026-11-13）

本规范要解决的问题不是"读得不够"，而是**读得没有结构**。本工程已经真实发生过的事故：

- 一个 287 行的类，用 40～70 行的窗口读了 6 次，方法的**声明**和**调用点**从未同时出现在视野里，改签名后漏改 3 处调用点；
- 根目录躺着 5 个 `tmp_*.txt` 反编译转储，合计 **约 950 KB**，其中单个 522 KB，读一次就爆掉可用的上下文；
- 搜 `fabric-modules` 时正则写错返回空结果，把"没搜到"当成"不用查"，直接凭记忆写了错误的包名。

三条都不是信息量太大，而是**没有索引、没有分级、没有把结论落成可引用的记录**。

---

## 1. 核心原则

> **先索引，后定位，再读取。默认不整读。**

| 原则 | 含义 | 代价对比 |
| --- | --- | --- |
| 索引优先 | 任何"这个功能在哪个文件"的问题，先查 `INDEX.md`，不要靠扫描目录猜 | 索引 1 次 ≈ 200 行；全库 grep 一次 ≈ 数千行 |
| 定位优先 | 明确知道要找什么（函数名、常量、字符串）时，用 `grep` 拿行号，不读文件 | grep 结果 10 行 vs 整读 287 行 |
| 最小充分 | 读"刚好能完成任务"的最小范围，且**必须包含该修改涉及的全部相关行** | 见 §2 分级 |
| 结论落地 | 读到的签名/常量/路径，立刻写进 `tmp\api_notes.md`，之后引用笔记而不是记忆 | 一次记录 ≈ 1 行 vs 一次记错 ≈ 一轮返工 |

## 2. 文件分级与读取方式

按**物理规模**分级，不按重要性分级。

| 级别 | 判据 | 允许的手段 | 禁止 |
| --- | --- | --- | --- |
| **L0 索引级** | 只判断"是否存在/在哪" | 查 `INDEX.md`、`Get-ChildItem` 列名 | 打开内容 |
| **L1 定位级** | 找单个符号/字符串 | `grep` / `Select-String`，只看匹配行+行号 | 读上下文超过 3 行 |
| **L2 窗口级** | 改单个局部（一个方法、一个常量） | `read` 的 `offset`/`limit`，**窗口 ≤ 80 行** | 用于跨方法/跨区块改动 |
| **L3 整读级** | 文件 ≤ 400 行 且 ≤ 20 KB，且本次要改**签名/字段/继承关系** | 一次整读（`read` 不带 `limit`） | 分多次窗口读 |
| **L4 扫描级** | 文件 > 400 行、> 20 KB、或日志/转储/jar | **必须交给脚本**：只输出摘要（行数、匹配行、统计） | 用 `read` 打开原文件 |

### 必须升级到 L3 的四种情况

满足任意一条，**不许用窗口读**：

1. 要改方法**签名**（参数/返回值/可见性）；
2. 要改**字段名或类型**；
3. 要改**类声明**（extends/implements、record 组件）；
4. 该文件**本轮已被窗口读 2 次以上**（第 3 次就该整读）。

> 这条直接对应本工程 287 行渲染器的漏改事故。窗口读的本质缺陷是：**你看到的相邻行不代表相关行**。

### 一个正例

`PortalLinkRenderer.draw()` 是分发点，`drawGhost()` 是它的被调方，两者相距约 100 行。改 `drawGhost` 签名时，L3 整读一次（287 行）能同时看到：

- 第 94～107 行的 5 个调用点；
- 第 112～250 行的 5 个声明；
- 第 14～22 行的常量区（`LABEL_BASE_SCALE` 等）。

## 3. 反模式表

| # | 反模式 | 真实症状 | 正确做法 |
| --- | --- | --- | --- |
| A1 | 窗口化石阅读长文件 | 声明与调用点分离，漏改 3 处 | §2 的 L3 升级条件 |
| A2 | 读完不落笔记 | 十分钟后凭"印象签名"写代码，编译失败 | 读到签名立刻写 `tmp\api_notes.md` |
| A3 | 空搜索当"无需查询" | 正则写错返回 0 条，直接猜包名 | 空结果 ≠ 不存在；换关键词/换范围再搜一次，仍空则**列为未知并显式验证** |
| A4 | 直接读反编译转储 | 单文件 522 KB，一次读爆 | 用脚本 `Select-String` 抽取目标方法段，或只读 `javap -public` 的签名摘要 |
| A5 | 用 `read` 打开二进制/jar/图片 | 输出乱码或巨大 | jar 用 `javap`/`ZipFile` 列条目；图片用 `read_image` |
| A6 | 反复读同一文件的同一段 | 同一 40 行读了 4 次，共 160 行无效输出 | 第二次读同一位置即触发 L3 整读并记账 |
| A7 | 全文 grep 不看命中数 | 一次 250+ 命中，等于没定位 | 先加文件名过滤或更具体的正则，命中 ≤ 20 再读 |
| A8 | 把临时文件堆在根目录 | 根目录 5 个 `tmp_*.txt`，约 950 KB | 一律进 `tmp\`，过期即删（见 §7） |
| A9 | 依赖"我记得"的记忆 | 上下文压缩后，摘要保留结论、丢失参数表 | 以磁盘为准；压缩后的记忆一律视为待验证 |
| A10 | 一次读全仓库 | 用 `read` 遍历源目录 | 只有脚本可以全仓扫描，且只输出统计 |

## 4. 索引表设计

索引文件：**`INDEX.md`**（工作目录根，由 `tools\file-index.ps1` 生成，勿手改）

### 4.1 列定义

| 列 | 用途 | 维护方 |
| --- | --- | --- |
| 路径 | 相对工作目录，可直接复制给 `read` | 脚本 |
| 类型 | java / resource / doc / tool / scratch | 脚本 |
| 行数 | 触发 L2/L3/L4 分级的依据 | 脚本 |
| KB | 判断是否属于"大文件" | 脚本 |
| 用途 | 一句话职责，**稳定性最高**的信息 | 人工（`tools\file-index-notes.txt`） |
| 关键符号 | 类名 + 主要方法名，用于"改签名前 establishing 影响面" | 脚本自动抽取 |
| 更新时间 | 判断是否为近期改动区 | 脚本 |

### 4.2 为什么"用途"必须人工维护

脚本只能抽取符号，抽不出**语义**。而本工程真正高频的问题是"这个功能该改哪个文件"，不是"这个方法叫什么"。

因此：

- 新增/重命名的源文件，**必须在 `tools\file-index-notes.txt` 里加一行**：`相对路径=一句话用途`；
- `file-index.ps1 -Check` 会对未标注的源文件报错；
- 用途写"这个文件负责什么"，不写"这个文件有什么"。

例：

```
portallink/src/main/java/com/heishan/portallink/core/LinkageResolver.java=纯函数实现原版传送门最近匹配算法（含对称性冲突判定）
portallink/src/main/java/com/heishan/portallink/client/scan/PortalScanService.java=组装快照：服务端 POI（权威）/ 客户端区块（兜底）
```

## 5. 检索决策树

```
需要知道某功能在哪
├─ 语义层：这是"传送门链接计算"吗？
│   └─ 查 INDEX.md 的"用途"列 ──► 得到 1~2 个候选文件
└─ 符号层：已知类名/方法名/常量名？
    └─ grep 全仓（只搜 *.java） ──► 得到行号 ──► 按 §2 决定 L2 还是 L3

需要改某方法签名
├─ 1. grep 该方法名（全仓，含非 java 的调用点，如测试、脚本）
├─ 2. 把命中清单写进 tmp\edit_plan.txt（文件:行号:调用形态）
├─ 3. 对清单里每个文件判定读取级别
├─ 4. 整读（L3）→ 一次性改完
└─ 5. 立即 compileJava，不跨工具调用攒改动

需要看 Minecraft/Fabric API
├─ 只要签名 ──► javap -public <类> ──► 抽 1 行写进 tmp\api_notes.md
├─ 要语义（为什么这么判） ──► javap -p -c ──► **管道给 Select-String 取目标方法段**，不落盘整份
└─ 要整类结构 ──► javap -p 后只看字段/方法列表
```

## 6. 大文件与"巨量"信息处理

### 6.1 反编译输出

**禁止**：`javap ... > tmp_x.txt` 然后 `read tmp_x.txt`。本工程的 `tmp_mc.txt` 就是 522 KB。

**允许**：

```powershell
# 只取某个方法的字节码段（约 40 行）
$t = javap -p -c -cp $cp net.minecraft.world.level.portal.PortalForcer
$i = ($t | Select-String 'findClosestPortalPosition' | Select-Object -First 1).LineNumber
$t[($i-1)..($i+40)] -join "`n"
```

```powershell
# 只要签名
javap -public -cp $cp net.minecraft.gizmos.Gizmos | Select-String 'billboardText|cuboid|line\('
```

### 6.2 日志

`run\logs\latest.log` 常见数 MB。**永远带过滤**：

```powershell
Select-String -Path run\logs\latest.log -Pattern 'ERROR|Exception|Caused by' |
  Where-Object { $_.Line -notmatch 'authlib|Realms|401' } |
  Select-Object -Last 30
```

需要看完整上下文时，只取**错误行前后 10 行**，不整读。

### 6.3 jar / 二进制

```powershell
# 列条目，不读内容
Add-Type -AssemblyName System.IO.Compression.FileSystem
$z=[System.IO.Compression.ZipFile]::OpenRead($jar)
$z.Entries | Where-Object { $_.FullName -like '*keymapping*' } | Select-Object -ExpandProperty FullName
$z.Dispose()
```

### 6.4 阈值表

| 指标 | 阈值 | 触发动作 |
| --- | --- | --- |
| 单次工具输出行数 | ≤ 200 行 | 超出则改用脚本聚合 |
| 单次工具输出字节 | ≤ 16 KB | 超出则先过滤再输出 |
| 单个源文件 | ≤ 300 行 / ≤ 15 KB | 超出则**拆分**（本工程硬要求） |
| 单个非源码文件 | ≤ 1 MB | 超出则禁止 `read`，只能脚本摘要 |
| grep 命中数 | ≤ 20 条 | 超出则加过滤条件 |
| 同一位置重复读取 | 2 次 | 第 3 次强制升 L3 并记录原因 |

## 7. 写入侧治理（目录卫生）

读取问题一半是写入造成的。

### 7.1 目录职责

| 目录 | 只允许放 | 生命周期 |
| --- | --- | --- |
| `portallink\src` | 源码与资源 | 永久 |
| `portallink\` 根 | README、mod_context、复盘文档、gradle 文件 | 永久 |
| `tools\` | 可复用脚本 + 其配置（notes） | 永久 |
| `tmp\` | 一切临时文件：转储、探针、截图、笔记 | **会话内删除** |
| `tmp\work\` | 进行中的临时文件 | 会话结束清空 |
| `backup\` | zip 备份 | 保留最近 20 个 |
| `logs\` | 脚本运行日志 | 保留最近 10 个 |

### 7.2 命名约定

| 内容 | 命名 | 例 |
| --- | --- | --- |
| 反编译转储 | `tmp\dump_<类名简写>.txt` | `tmp\dump_PortalForcer.txt` |
| 方法片段 | `tmp\snip_<类>_<方法>.txt` | `tmp\snip_PoiManager_getInSquare.txt` |
| 笔记 | `tmp\api_notes.md` | 固定名，持续追加 |
| 编辑计划 | `tmp\edit_plan.txt` | 固定名，每次覆盖 |
| 构建日志 | `tmp\build.log` | 固定名，每次覆盖 |

### 7.3 清理规则

- 根目录**禁止**出现 `tmp_*.txt`（当前 5 个，约 950 KB，见 §8）；
- `tmp\` 内超过 3 天的文件，在下次备份前删除；
- 任何非本工作目录的落盘（`E:\Project\portallink` 之外的 `*.txt` 等）都是违规，必须回迁。

## 9. 自动化工具

### 9.1 生成索引

```powershell
cd E:\Project\portallink
.\tools\file-index.ps1
```

输出 `INDEX.md`，并在控制台打印：文件数、总行数、超 300 行的文件、未标注用途的源文件。

### 9.2 索引检查（CI 式门禁）

```powershell
.\tools\file-index.ps1 -Check
```

退出码非 0 表示有违规（超长文件 / 未标注 / 根目录散落临时文件）。

### 9.3 与备份纪律的衔接

`tools\backup.ps1` 打包前，先跑一次 `file-index.ps1`，保证索引与源码同步：

```powershell
"改动说明" | Out-File -Encoding utf8 tmp\next_op.txt
.\tools\file-index.ps1            # 刷新索引，顺便暴露违规
.\tools\backup.ps1 -OpFile .\tmp\next_op.txt -Tag <标签>
```

### 9.4 已验证的运行结果

| 命令 | 结果 |
| --- | --- |
| `.\tools\file-index.ps1` | `files=48 lines=4524 kb=356.4`，`no violations` |
| `.\tools\file-index.ps1 -Check` | `INDEX CHECK OK`，退出码 0 |
| 清理前 `-Check` | 8 条违规（根目录 `tmp_*.txt`），退出码 1 |

索引文件本身**不计入统计**（否则每跑一次总数都会变），这一点在脚本里显式跳过 `INDEX.md`。

## 10. 操作前检查清单

改任何文件之前，逐条确认：

- [ ] 我查过 `INDEX.md`，知道要改的是哪 1～2 个文件？
- [ ] 这次是改签名/字段/类声明吗？如果是，是否已 L3 整读？
- [ ] `grep` 出的调用点清单写进 `tmp\edit_plan.txt` 了吗？
- [ ] 我要用的 API，签名是从 `javap` **当场读到**的，还是"我记得"？
- [ ] 上次 `compileJava` 是多久之前？如果中间改过代码，现在是否通过？
- [ ] 有没有产生新的临时文件？它在 `tmp\` 里吗？
- [ ] 如果我失败了 2 次，是否已停下写"当前假设 + 下一验证步骤"？
